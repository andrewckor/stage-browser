Stage is a minimal Chromium browser for workshops, webinars and demos. Share the window and your audience sees the site, edge to edge. Your tabs wait behind the top edge until you reach for them.

Run of show.

  1. Before the call

    Open your demo tabs from the terminal

    stage --size 1280x720 \ app.example.com docs.example.com

    Each address becomes a tab. --size fixes the window at 16:9, so nothing reflows when you start sharing.

  2. Going live

    Share only the Stage window

    In Zoom, Meet or Teams, pick the Stage window instead of your whole screen. The audience gets the page and nothing around it.

  3. During the demo

    Reach up when you need another tab

    Push the pointer against the top edge and the tabs slide in. Or stay on the keyboard: ⌘1–⌘9 switch tabs and ⌘L opens a page.

Small on purpose.

Hidden tabs

No toolbar, address bar or bookmarks. The tab capsule slides over the page from the top edge, and ⇧⌘B pins it open.

Extensions

Add the ones you use from the Chrome Web Store: open the Chrome Web Store from the Extensions menu, go to the extension's page, then choose Extensions → Add Extension from This Page. Their icons sit in the tab bar.

Terminal start

stage <url> opens the page and hands your prompt back. Run it again and the page joins the open window. No app bundle to sign.

Share sizes

Window presets at 1280×720, 1440×900, 1600×900 and 1920×1080. Zoom with ⌘= and ⌘- so the back row can read.

Escape hatch

⇧⌘O opens the current page in Google Chrome. Zoom and Slack links open in their own apps.

One command.

Try it without installing

npx stage-browser https://example.com

Install the stage command

npm i -g stage-browser

Needs macOS and Node 18 or later. The first run downloads Chromium, about 100 MB.

Before you go live.

Do Chrome extensions work?

Most do. Stage starts with none installed. Open the Chrome Web Store from the Extensions menu, go to the extension's page, then choose Extensions → Add Extension from This Page. Stage shows what it can access before adding it, checks the package against Google's signature like Chrome does, and updates it automatically. The Web Store's own Add to Chrome button doesn't work in Stage. Pop-ups open from the tab bar. Stage supports most Chrome extension APIs but not every one, so if an extension misbehaves, ⇧⌘O opens the page in Google Chrome.

Is it signed or notarized?

It doesn't need to be. On first launch, Stage copies Electron's Chromium app on your own Mac, names it Stage, and gives it a local signature, the same kind Electron itself ships with. No Apple developer account is involved.

Why does macOS ask about "Chromium Safe Storage"?

That Keychain key decrypts your saved logins. macOS asks once after you install or update Stage. Choose Always Allow, or sites will treat you as signed out.

Where are my logins and tabs kept?

In ~/Library/Application Support/Stage. npx, a global install and a clone all share it, so you sign in once. Stage reopens your last tabs when it starts.

Windows or Linux?

Not yet. Stage is macOS only.
